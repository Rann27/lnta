# LNTA (LN Translation Agents)

LNTA is an open-source Windows desktop application designed to run a structured, deterministic Japanese light-novel and web-novel translation pipeline directly from a project volume folder.

Built with **Tauri 2**, a high-performance **Rust** core, and a **React + TypeScript** frontend adhering to the Tally design system, LNTA replaces agentic orchestrator overhead with deterministic system processes, invoking AI models only for language translation and semantic review.

---

## What LNTA Does

In traditional agentic pipelines, significant tokens and time are lost having AI agents manage file reading, chapter chunking, docx formatting, and QA book-keeping. LNTA handles orchestration natively in Rust:

- **Deterministic Pipeline:** Parses raw chapters, normalizes furigana ruby markup, extracts titles, plans token-safe chunk parts, and tracks translation state in an embedded SQLite database.
- **DOCX Generation:** Directly generates and updates `Translations.docx` matching standard layout conventions (Letter page size, margins, paragraph breaks, heading styles, and standalone full-page illustration layout).
- **Multi-Role AI Execution:** Dispatches translation, repair, QA review, and QA fixing to separate configurable models, each with ordered fallbacks.
- **Providers:** Anthropic, OpenAI, Google Gemini, xAI Grok, DeepSeek, Z.ai GLM, Alibaba Qwen, MiniMax, Xiaomi MiMo, Moonshot Kimi, Mistral, the OpenRouter gateway, and any other OpenAI-compatible endpoint (including local servers). Subscriptions work through their official CLIs: Claude Code (Claude Pro/Max), Codex CLI (ChatGPT Plus/Pro), and Antigravity CLI (Google AI Pro/Ultra), each signed in once in a terminal.
- **Comprehensive QA Scanner:** Performs dozens of profile-specific QA checks across Indonesian (`ja-id`) and English (`ja-en`) profiles, applying mechanical fixes with full versioned undo support.
- **Privacy & Security:** Runs entirely locally; API keys are kept in the OS credential manager and network traffic is restricted solely to AI model provider endpoints.

## Project Folder Layout

LNTA works directly with standard volume project folders. An active volume folder typically looks like:

```text
Volume-Directory/
├── 1_prologue.md             # Raw chapter files (ordered by numerical prefix)
├── 2_chapter1.md
├── 3_chapter2.md
├── instruction.md            # User-supplied translation guidelines
├── glossary.md               # Project glossary (source === target === notes)
├── Translations.docx         # Target document generated by LNTA
├── illustrations/            # Volume illustration images (e.g. p001.jpg, color01.png)
└── .lnta/                    # Internal workspace (database, backups, configuration)
    ├── project.toml          # Project configuration overrides
    ├── lnta.db               # SQLite translation history and QA records
    └── backups/              # Rolling atomic backups of docx and glossary
```

> **Note on Instruction Files:** Users bring their own instruction file (such as `instruction.md` for Japanese to Indonesian or `instruction-en.md` for Japanese to English) containing their desired stylistic guidelines, honorific rules, and formatting preferences. LNTA sends this file whole to the translator role without summarization.

## Getting Started & Build Steps

### Prerequisites

- **Node.js**: v18.0.0 or later (LTS recommended)
- **Rust**: 1.78.0 or later with `cargo`
- **Build Tools**: Microsoft C++ Build Tools (on Windows)

### Installation

Clone the repository and install frontend dependencies:

```bash
git clone https://github.com/Rann27/lnta.git
cd lnta
npm ci
```

### Running in Development

To start the desktop application in Tauri development mode:

```bash
npm run tauri dev
```

To run the frontend in browser preview mode with mock IPC (for UI development without Tauri runtime):

```bash
npm run dev
```

### Running Tests and Linting

LNTA maintains strict code quality and guard verification:

```bash
# Run full validation suite (TypeScript, ESLint, Guards, i18n, Vitest, Rust clippy, and Cargo tests)
npm run check

# Run Rust unit tests only
cargo test --manifest-path src-tauri/Cargo.toml

# Run Vitest frontend tests only
npm test
```

### Building the Release Installer

To build the production Windows installer:

```bash
npm run tauri build
```

The resulting standalone executable and setup installer will be placed in `src-tauri/target/release/bundle/`.
